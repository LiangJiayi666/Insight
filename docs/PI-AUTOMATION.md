# Pi 日报运行手册

项目只保留一条新闻制作途径：`scripts/pi-daily.mjs` 启动独立 Pi，使用 Pi 全局 Exa MCP 搜索和读取正文，再由本地程序校验与发布。没有独立 Exa REST 客户端、另一套模型采编流程或隐式备用新闻源。

## 命令

| 命令 | 用途 |
| --- | --- |
| `npm run pi:check` | 仅检查 Pi CLI 路径，不联网 |
| `npm run pi:smoke` | 调用现有 Pi 模型和 Exa，生成一条测试新闻，不发布 |
| `npm run daily:pi` | 先按日期补缺失刊期，再制作当天日报；每期目标 12 条，证据不足则少发 |
| `npm run daily:pi -- --resume-date=YYYY-MM-DD --no-sync` | 恢复已有刊期检查点；本地发布，跳过脚本的 Git 同步 |
| `npm run daily:pi -- --backfill-date=YYYY-MM-DD --no-sync` | 仅补指定历史日期；没有检查点也可创建，不制作当天刊期 |
| `npm run build` | 从最新结构化稿件重建页面，不获取新闻，不调用模型 |
| `npm run build -- YYYY-MM-DD` | 重建指定历史刊期；旧刊不会替换最新首页 |
| `npm start` | 仅在本机预览 `public/`，默认端口 4173 |
| `npm run unlock` | 确认锁的进程已退出后清理残留日报锁 |
| `npm test` | 离线测试，不使用真实模型或飞书账号 |

## 配置

- `config/pi.json`：CLI 路径、模型、超时、每刊进程尝试上限（字段名 `maxAttemptsPerDay`）、工具列表及项目信任设置。CLI 路径也可由 `INSIGHT_PI_CLI` 指定。
- `config/settings.json`：目标条数、制作时间、首次回看小时数、单刊最大回看小时数。日期统一按北京时间计算。
- Pi 自行加载当前用户的全局模型认证和 Exa MCP 配置；项目不读取 `.env`，不另配 `EXA_API_KEY` 或 `OPENAI_API_KEY`。

独立进程使用 `--print --mode json --no-session --no-approve`，允许 read、write、edit、tool_search 和 Exa 搜索/读取，不开放 shell。项目扩展限制write/edit只能修改本次bundle；恢复优先局部edit，避免重发整份JSON时遇供应商流中断。提示词要求不读认证文件，网页内容只作资料。
Pi 全局扩展仍会加载，工具列表不是操作系统沙箱；全局自动快照扩展也可能自行提交代码。`--no-sync`只控制本项目脚本的 Git 同步。

## 运行与恢复

正式 Pi 进程默认最长 90 分钟，测试最长 10 分钟，每个刊期累计最多 3 次尝试，一次启动对每个待办刊期最多调用一次 Pi。制作与离线重建共用日报锁，已发布刊期制作直接跳过。重试保留检查点、固定采集窗口和成功缓存；已有合格 bundle 可以直接发布，搜索冷却不会阻止该步骤。

Pi每次write/edit本刊bundle后，会立即收到与外层发布一致的本地校验结果；保存成功但校验失败时，在同一次Pi运行内继续局部修复。选题校验一次列出全部错误候选及数组位置，避免每轮只修一个错误。外层仍再次校验，不以模型自报成功为准。本地校验错误单独记录为validationError，不再误写为供应商错误。

普通运行从最早的正式刊期或检查点开始查找日期缺口，按从旧到新的顺序补刊，最后制作当天刊期；即使当天已发布，也会补中间的缺口。新建历史检查点截止于该日北京时间 23:59:59.999，起点使用前一日期刊的截止时间；前一期缺失时从本日零点开始。当天刊期截止于启动时刻，首次启动且无历史记录时才使用首次回看窗口。已经存在的检查点保持原窗口。

历史刊期会注明补建时间和回溯资料的限制，仍走同一条 Pi → Exa 制作流程。补旧刊只新增对应归档，不回退最新首页和全局截止时间。若某期冷却、超出尝试上限或校验失败，会记录错误并继续尝试后续刊期，最终以失败状态退出供维护任务发现；不会把缺失日期静默并入当天刊期，也不会自动重置尝试次数。

2026年11月14日补刊使用15日期刊已经保存的正文证据和稿件，按历史窗口重新取舍，共7条，没有再次联网检索。补刊已注明它不是当日完整新闻清单，且与原15日跨日刊期存在重复；原15日归档保留。

搜索与正文读取串行执行，间隔至少 8 秒，每刊搜索最多24次、读取最多36次、合计最多60次，分项和合计都由程序限制；连接测试为4次搜索及3次读取。启动和每次Exa结果后向Pi返回真实累计用量与剩余预算。旧检查点从工具日志恢复分项计数；缓存命中与本地冷却拦截不计联网次数，真实失败请求计入。成功结果缓存到本刊目录，重复请求提示读取缓存。只从失败工具结果判断服务端限流，真实 429 冷却 15 分钟；文章 URL 或正文出现数字 429 不会触发冷却。

11月15日曾发生成功 URL 中的429被误判、后续读取被拦截的问题，已修复并恢复出刊。那次使用的一次性日志恢复/尝试返还代码现已移除，原始日志及修复记录仍保留在私有运行目录。

无有效正文、时间窗口不符、主来源重复、引文无法匹配或候选取舍记录缺失时不发布。证据由模型从工具返回整理；结构和引文检查不等于独立事实核验。

重大候选入选仍必须有实际读取的独立来源URL。未入选候选若真实搜索失败或没有找到独立原文，可保留空followUpUrls并提供followUpAttempts（真实query、result、detail，可选url）；result仅为no-independent-source、unavailable、rate-limited。必须标为unverified/excluded、不关联正文storyId，并在刊期notice说明覆盖缺口。未经尝试或仅声称预算耗尽不能通过；不会把未核实候选写进正文。合并候选标为excluded并说明合并对象，不能使用merged等未定义状态。

2026年11月17日晚间制作因未入选重大候选缺少追查URL被整期拦截，另有恢复时误判搜索预算耗尽。11月18日修复上述失败记录、实时校验反馈和预算计数。补刊保留原时间窗口、正文证据和失败候选，不用删除审计记录或伪造URL恢复发布。

恢复结果：16日5条、17日8条均通过完整校验并发布。16日根据原始失败工具记录补充追查失败项；17日由Pi实际新增3次搜索和1次批量读取取得独立报道，再据缓存修正两条候选审计。恢复中的整份JSON重写遇供应商连接中断及502，保留日志后停止该进程，按已取得的工具记录完成局部修复；正文与证据未改写。后续恢复已启用受限edit与即时校验。原稿、修改依据及进程中断原因保存在对应私有刊期目录。

## 历史数据与分析质量

正式制作和恢复都执行历史研究校验，连接测试不要求完成经济研究。增长、统计和利率类新闻要先查历史再写分析，至少将三分之一检索/读取预算留给原表、前次决定及背景；质量优先于12条目标。历史资料可以早于主新闻窗口，官方背景表只有日期也可使用，不能为了精确时刻伪造时间或丢弃来源。

每条适用的新闻包含 `history`：实际/预测分开的序列、统计口径、期间、数值、来源和逐字引文，以及指向同一序列两个期间的比较。完整研究须有实际历史序列、前一期和上年同期比较；季度至少4期且包含上年同季，月度/年度/利率至少3期，决议利率需覆盖至少一年。预测版本修订不能代替已实现的增长走势；不同期限与工具不能混在同一序列。

页面直接展示带出处的历史表，程序计算百分点、基点、水平值差和水平值增长率，拒绝把利率或增速再计算百分比涨幅。增速之差与GDP本身的同比/环比是不同量，提示词要求单独说明；季调、实际/名义、修订版本和因果解释仍需编辑核对。

如果查不到可比资料，必须给出缺口及具体查询/URL/失败原因，通常先查官方再查替代来源；真实限流时立即停止。只能作为明确标识的资料受限简讯，不能用四段泛泛分析或假设算例填充。程序检查记录结构、期间覆盖和引文，但检索尝试、指标归属和口径含义仍包含模型判断，不能把通过校验当作事实与分析全部正确。

此要求用于新制作及未发布稿件的恢复。已发布历史页面不会因新门槛而自动改写，离线重建仍兼容旧稿结构。排查依据见 [分析质量检查](EDITORIAL-QUALITY.md)。

## 文件与调度

| 路径 | 内容 |
| --- | --- |
| `data/pi-runs/YYYY/MM/DD/` | 检查点、进程心跳、提示词、bundle、缓存和私有日志 |
| `data/pi-smoke/` | 不发布的联网测试结果 |
| `data/issues/YYYY/MM/DD/issue.json` | 正式结构化稿件 |
| `data/evidence/YYYY/MM/DD/` | 正文证据与选题记录 |
| `data/runtime/state.json` | 成功刊期与上次采集截止时间 |
| `public/index.html`、`public/issues/` | 最新页面与历史刊期 |
| `archive/` | 早期原型和试刊，仅作历史资料，不参与制作或预览回退 |

`Insight-Daily` 每天北京时间19:50执行 `scripts/pi-daily.mjs`。安装或更新使用 `scripts/install-task.ps1`；卸载追加 `-Remove`。任务不设整批两小时硬截止，避免补刊占用时间后强制中断当天刊期；每次 Pi 调用仍受自身超时约束，任务禁止并行重复启动。需要电脑开机、当前用户登录并联网，睡眠会延迟运行。飞书发送和备份由单独的维护任务执行，见 [维护手册](OPERATIONS.md)。

只将 `public/` 用作站点目录。运行日志、缓存和证据可能包含完整来源内容，不公开、不提交。
