# Exa限流政策与本机证据

核查日期：2026年11月18日。线上配置和套餐会变，以下分开记录官方文档、官方源码默认值、本机证据及本地策略。

## 官方政策

| 接入方式 | 适用限制 | 证据与边界 |
| --- | --- | --- |
| 无Key、未登录的托管MCP | 免费限流；开源实现按出口IP检查秒级频率与日累计 | [官方MCP说明](https://exa.ai/docs/get-started/exa-mcp)；[服务端源码](https://github.com/exa-labs/exa-mcp-server/blob/main/api/mcp.ts)。源码默认2 QPS、50次/日，`RATE_LIMIT_QPS`和`RATE_LIMIT_DAILY`可覆盖，不能证明线上当前阈值。 |
| API Key或OAuth账户 | 按团队与端点限流，个人Key还可设置更低额度 | [计费与限流文档](https://exa.ai/docs/admin/billing)：普通搜索默认10 QPS，deep类5 QPS，contents 100 QPS；套餐、共享端点及单Key限制可能不同。 |
| 余额或Key预算不足 | 402，不是429 | [错误码文档](https://exa.ai/docs/admin/error-codes)。等待几分钟不能保证恢复余额。 |

QPS是每秒请求数，不是一个对话或日报最多查多少次。免费MCP的源码对`tools/call`计次，协议初始化、工具列表不计入这层限制；搜索和读取都可能消耗同一个免费MCP额度。一个批量读取工具调用不等于只读取一篇网页；账户计费又是另一套单位。

免费MCP的429返回`Retry-After`与重置时间，源码把`X-RateLimit-Limit`和`Remaining`都写为0，以隐藏究竟触发了秒级还是日累计限制。0不能解读成账户永久没有额度。请求应遵守服务端的等待时间；无时间信息时官方建议指数退避。API账户也有计划限制，不能把免费MCP错误里的“使用自己的Key”理解为无限使用。

## 为什么手动Pi与日报表现可能不同

本机核查发现：Windows任务使用当前登录用户；工作目录为Insight；自动入口加载同一用户全局Pi配置，没有单独的Exa客户端。全局Exa地址是`https://mcp.exa.ai/mcp`，没有Key参数、认证头或另设认证配置；未发现Exa OAuth凭据。项目本地没有覆盖用的`.pi/mcp.json`。凭据值没有写入本报告或日志。

因此没有证据表明“手动Pi有无限额度，自动程序被Exa专门限流”。能确定的差异是旧自动扩展额外施加了24/36/60次、8秒间隔和15分钟冷却。手动Pi不加载这些项目规则。

另一个实际差异是自动脚本此前选择未打包`dist/cli.js`，而安装后的手动`pi`命令使用`dist/bundle/cli.js`。现已优先使用后者，并保留用户显式配置。官方入口的帮助命令在本机约2.2秒返回，带或不带响应观察模块均成功；未打包入口启动更慢。这解释了部分启动差异，不能证明其导致了历史429。

真正的服务端限流还会受累计用量、请求是否集中、是否共用出口IP影响。代理或VPN可能让多个使用者共用出口，API/OAuth认证也会改变限流归属。但本次没有过去两种运行的出口IP、账户实际用量或响应头对照，不能断言是哪一项导致了每次历史429，更不能仅凭“手动没看到错误”推导没有服务端限制。

Pi是客户端，Exa Agent是另一项服务；Exa Agent运行并发上限不是Pi客户端数量上限。

## 当前实施规则

- 正式刊期取消旧的固定次数上限和8秒间隔，保持每次只有一个Exa工具调用在执行，复用成功缓存。
- 只对实际失败的429做限流处理，优先`Retry-After`，其次重置时间；接收服务端要求一天等待时，不擅自缩成15分钟。
- 未收到服务端时间才使用本地30、60、120秒递增退避，最高15分钟。连续429最多重试2次，下一次成功重置；需要等待超过60秒时保存状态、停止该次联网工作。参数见`config/pi.json`的`exaPolicy`，这些是运行策略，不是Exa官方额度。
- 各刊期共享项目级的服务端等待状态。原有90分钟进程超时、每刊3次进程尝试上限继续负责防止任务无限运行；它们也不是Exa额度。
- 402及401/403单独停止。缓存仍可使用，已有合格稿件不因服务冷却而禁止发布。
- Node预加载观察Pi原有请求的响应头，不追加联网请求、不记录Key、授权头、查询内容或带Key的URL。保留响应状态、工具名、时间与限流头，使后续能依据服务端响应审计。

本次验证使用模拟响应及离线测试，没有故意持续请求Exa以制造429或测出免费额度。
