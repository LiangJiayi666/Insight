# 自动日报运行手册

## 状态和边界

第一阶段代码已实现：搜索采集、正文与时间过滤、事件选题、背景检索、结构化撰写、逐字引文检查、模型证据一致性审查、HTML生成、日期归档、任务锁、断点恢复、预算和日志。目标12条，不足则明确标注实际数量及分类缺口。没有可靠条目时不更新首页。

本次实现使用Exa REST API进行白名单域名搜索及正文提取，不是全量订阅所有网站。尚未实现RSS连接器、SQLite事件库、自动保留期清理、跨日事件图谱和网页托管。当前使用原子写入的JSON检查点管理状态，后续可以迁移SQLite。语义事件去重依赖模型，程序另做URL去重、来源不可重复分配；不能保证识别全部重复事件。

飞书属于第二阶段，本版未实现发送，也没有部署公网网页。

## 配置

1. 在项目目录把 `.env.example` 复制为 `.env`。
2. 填写 `EXA_API_KEY`、`OPENAI_API_KEY`、`OPENAI_MODEL`。
3. 如使用兼容服务，配置 HTTPS 的 `OPENAI_BASE_URL`，末尾通常为 `/v1`。
4. 执行 `npm run check`。

`check` 仅检查字段和HTTPS地址，不验证账号额度、模型兼容性或检索权限。模型服务需支持 Chat Completions、JSON object输出和 `max_tokens`。不同供应商接口可能需要适配。当前聊天工具的权限不自动等于后台API密钥，请勿把密钥发在聊天或写入HTML。

## 首次真实运行

```powershell
npm run daily
npm start
```

浏览器打开 http://127.0.0.1:4173 。首个自动日报完成后服务器优先提供 `public/index.html`；之前提供根目录的5条试刊。直接双击新的 `public/index.html` 也可以阅读。

`npm run daily` 会调用付费服务。首次24小时窗口，此后从上次成功截止时间继续，最多回补72小时，超出会标明遗漏。一天成功一次后重复执行会退出，不重写当期。当前不支持按旧日期重跑或强制更正，以免误覆盖。

查看页面后，应人工抽查至少：新闻是否真在窗口内、日期是否来自原文、数字是否准确、机构案例与历史关联是否有支持、假设与分析是否标记。代码和离线测试通过不等于新闻真实性得到保证。

## 预算与时间

`config/settings.json`：

- `targetStories: 12`：最多12条合格新闻，不凑数。
- 搜索5个主题，每主题最多8个结果，URL去重后最多40个候选。
- 背景检索最多12次；所有搜索请求含重试最多20次。
- 模型请求含重试最多27次：通常1次选题、12次撰写、12次审查，余量用于失败重试。
- 每次模型输入最多110,000字符、输出最多4,500 tokens；这不是美元预算，不同模型费用不同。
- HTTP超时90秒，最多2次尝试；认证及一般参数错误不重试。
- 来源主题与域名在 `config/sources.json`。单一通讯社转载不能当独立核实。

初始检索和正文摘要可能遗漏事件；审核未通过时本版不会额外补选候补，因此实际条数可能少于12。以后可在预算允许时增加候补队列。

## 文件组织

```text
config/                         设置与来源白名单
src/                            采集、编辑、流水线与运行支持
scripts/                        CLI、预览、生成和任务安装
public/index.html               最新自动日报（唯一公开目录）
public/issues/YYYY/MM/DD/        每日HTML及配套资源
 data/runtime/state.json        上次成功窗口与发布记录
 data/runtime/daily.lock        全局任务锁
 data/runs/YYYY/MM/DD/           检查点、选题、草稿和审核状态
 data/raw/YYYY/MM/DD/            规范化采集正文（截断，不是完整网页存档）
 data/evidence/YYYY/MM/DD/       每事件证据包
 data/issues/YYYY/MM/DD/         正式结构化日报issue.json
logs/YYYY/MM/YYYY-MM-DD.jsonl    不含密钥的阶段日志
```

原有 `index.html`、`archive/` 和 `data/issues/2026-11-11.json` 留作试刊历史，未删除。`npm run build -- 2026-11-11` 仍用于重建旧试刊，不影响自动日报公开目录。

只能发布 `public/`，不要把项目根目录设为站点目录。`data/raw`及证据中可能包含受版权限制正文，仅作本地核对；长期保存与使用需符合服务授权。本版本不自动删除历史资料，避免误删；需定期检查磁盘，后续增加可审计的保留策略。

## 失败恢复

- 每个阶段保存检查点；同日失败重跑复用已成功步骤和原始截止时间。
- 来源失败可重试；没有草稿/审核结果的条目可继续处理，已明确拒绝的稿件不在同一检查点内重复审查。
- 每次请求前持久化请求计数；崩溃后可能保守多计，但不重置预算。
- 先写并验证当期文件，最后原子替换首页；失败不会把旧刊标成今天。
- 当期发布后但状态尚未保存时崩溃，可从ready检查点恢复发布，不再付费生成。
- 进程异常退出可能留锁。运行 `npm run unlock`，仅当对应PID已经不存在才清理；不会自动夺锁。
- 失败检查点存在时不允许修改配置后混跑。先恢复原配置，或人工备份并处理当期状态；删除检查点会丢失预算计数，可能导致重复付费。
- 日志只有阶段与计数，原始错误响应不写入日志。没有独立告警渠道，首期请查看命令退出码、Windows任务结果和日志。

## Windows定时任务

完成至少一次真实运行及内容抽查后，再手动执行：

```powershell
powershell -NoProfile -File .\scripts\install-task.ps1
```

默认北京时间19:50启动，读取settings中的scheduleLocalTime。脚本要求Windows时区为China Standard Time，使用当前用户的交互登录身份、普通权限，最大运行2小时，不允许并行。电脑必须开机且当前用户已登录、联网；休眠和关机会延误，StartWhenAvailable会尝试补跑，不保证20:30前完成。脚本不会修改系统执行策略；如被组织策略阻止，应使用允许的签名/任务安装流程。

移除：

```powershell
powershell -NoProfile -File .\scripts\install-task.ps1 -Remove
```

本轮未实际安装定时任务，避免缺密钥情况下每日报错。正式无人值守宜迁移常在线环境。
