# 用量与数据维护

2026-11-11启用。每日19:50制作；每日22:00由Windows任务Insight-Daily-Operations汇总当时可观测用量，将用量报告和当日日报单文件HTML分别发送到绑定飞书私聊，再备份及清理。需要电脑开机、用户登录、联网。任务失败最多间隔5分钟重试2次。22:00之后新增的调用会入账但不会补发当天第二份通知。

## 用量

`data/costs/YYYY/MM/DD.json`按运行文件唯一键汇总message_end，避免累加重复；包含Insight正式制作、测试及失败的已返回用量，不含普通飞书聊天。未返回usage的失败、旧文本日志标记不完整。缓存单列，不按普通输入估价。credits和money保持null，模型cost为0不代表免费。当前仍只有进程时间/次数限制，没有token或金额硬熔断。

`data/delivery-ledger/YYYY-MM-DD-cost.json`记录主动用量通知的状态与飞书message_id；重试复用uuid，成功后不重复发送。网络中断记uncertain，不宣称送达；飞书uuid去重有效期有限，无法承诺无限期exactly-once。接口成功也不证明用户已读。

`data/delivery-ledger/YYYY-MM-DD-daily.json`独立记录日报附件上传key、发送uuid及message_id。报告与附件分别去重，一方失败不阻止另一方尝试。当日日报不存在时仅发明确提示，不自动用旧刊替代；当天后来发布仍可通过“日报”指令获取。定时和手动现在统一调用deliverDailyReport：先发送当天用量台账，再发送当天附件；无当天刊时均发送明确提示，不退回旧刊。定时按日期去重；手动按消息ID去重，每次新发“日报”都再发送完整两份，且不重新制作新闻。2026-11-11已真实上传发送成功，重跑确认不重复发送。

原飞书桥接的message-ledger.json记录绑定用户命令ID和日报发送结果，保留30天。收到消息即落盘，崩溃窗口可能留下received而不再处理该条；用户重新发一条“日报”即可。未改变群聊不响应及绑定白名单。

## 存储

- 私有Pi事件日志保留30天，测试目录文件保留7天，重打包附件保留7天。
- 日报JSON、证据、用量台账长期保留。
- `data/source-results/`保存搜索/读取工具结束事件，区别于模型转录证据；可能包含服务截断文本，不等于网页原始HTML快照。私有目录，不部署。
- `backups/YYYY-MM-DD/`备份配置、稿件、证据、工具返回、台账及发布状态；每文件SHA256校验，保留7天。不备份凭证。每天备份发生在清理之前。
- 同盘备份只能防误修改，不能防整盘损坏；异盘/云端目标尚未指定，未自动上传。
- 测试已验证从备份读取issue.json重新渲染，与原始渲染一致。真实备份已逐文件hash校验，但没有做整机灾难恢复演练。
- 飞书config.json/owner.json关闭权限继承，仅当前用户与SYSTEM完全控制；仍为明文，同一用户下的程序仍可读取。

手动运行：`node scripts/operations.mjs`；追加`--notify`发送当天一次用量报告。通知失败不阻止备份清理。运行锁避免并发，进程崩溃残留operations.lock时须先确认无任务运行再人工移除。

## 界面

删除口号、Pi标识、黄色通知、逐条免责声明和算例/分析固定标签；来源与刊期资料说明保留在折叠区。正文中必要的假设条件保留。重新发送“日报”即可取得新版附件，旧消息内附件不会被替换。
